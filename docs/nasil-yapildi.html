1. Sistemin üç parçası

Neden bu ayrım?

GitHub Pages yalnızca dosya sunar; arkasında çalışan bir program yoktur. Çevrimiçi oyun için sürekli açık bir bağlantı ve ortak bir hafıza gerekiyor — onu Cloudflare Worker sağlıyor. Senin bilgisayarınla ilgisi yok; kod Cloudflare'in sunucularında çalışıyor, Mac kapalıyken de oda ayakta.

3. Poker: 7 karttan en iyi eli bulmak

Hold'em'de her oyuncunun 2 kartı, ortada 5 kart vardır. 7 karttan en iyi 5'liyi seçmek gerekir. 7'den 5 seçmenin 21 yolu var — az bir sayı, hepsini denemek en basit ve en güvenilir yol.

Her 5'li bir skor dizisine çevriliyor: ilk sayı el kategorisi (0 = yüksek kart … 8 = straight flush), sonrakiler beraberlik bozucular. İki el, bu diziler sözlük sırasına göre karşılaştırılarak kıyaslanıyor — böylece "aynı çift, kim daha yüksek kicker" gibi tüm ince durumlar tek bir karşılaştırmayla çözülüyor.

// 5 karttan skor dizisi — sözlük sırasıyla karşılaştırılır
function score5(cards) {
  const vals  = cards.map(c => c.v).sort((a,b) => b-a);
  const flush = cards.every(c => c.sk === cards[0].sk);
  // gruplar: [adet, değer] — önce adet, sonra değer büyükten küçüğe
  const shape = groups.map(g => g[0]).join('');   // '41' = dörtlü, '32' = full

  if (straightHi && flush) return [straightHi === 14 ? 9 : 8, straightHi];
  if (shape === '41')      return [7, ord[0], ord[1]];
  if (shape === '32')      return [6, ord[0], ord[1]];
  if (flush)              return [5, ...vals];
  ...
}
// Q♥J♦5♥8♥5♣ + Q♣K♣  →  [2, 12, 5, 13]  = iki çift (QQ 55, kicker K)

Doğrulaması kolay: 12 kategori için elle kurulmuş test elleri, kicker ve beraberlik testleri, ardından 10.000 rastgele el — hepsi geçti. A-2-3-4-5 (wheel) kenti gibi tuzaklar dahil.

Yan pot (side pot) mantığı

Biri 100 jetonla all-in olur, diğerleri 500 koyarsa, all-in olan yalnızca 100'e kadar olan kısmı kazanabilir. Algoritma katman katman ilerliyor: oyuncuların koyduğu farklı toplamlar sıralanıyor, her seviye bir "kat" oluşturuyor, her kat yalnızca o seviyeye kadar para koymuş oyuncular arasında paylaştırılıyor.

4. Blackjack: oyun ne kadar şansa bağlı?

Bunu tahmin etmek yerine ölçtük. rules.js içindeki gerçek fonksiyonlar bir simülasyona bağlanıp 3 milyon el oynatıldı. Aynı motor, üç farklı oynayışla:

OynayışKasa avantajıAçıklama
Temel strateji (botların oynadığı)%0,53Kumarhane standardında iyi bir oran
Krupiyeyi taklit (17'ye kadar çek)%5,7010 kat daha kötü
Asla batma (12'de dur)%7,9215 kat daha kötü

Sonuç: oyun şans değil. Kasanın yapısal bir üstünlüğü var (sen önce çekersin, battığında krupiye kart çekmeden kazanır) ama karar kalitesi kaybı 10-15 katına çıkarabiliyor. Kurallar bilinçli olarak oyuncu lehine: 3:2 blackjack ödemesi, krupiye soft 17'de durur, 4 ele kadar split.

5. Çevrimiçi masa: neden "otoriter sunucu"?

İki cihazın aynı masayı görmesi için ortak bir hafıza gerekiyor. En kolay yol paylaşımlı bir veritabanı olurdu — ama o zaman gizli bilgi sızar: krupiyenin kapalı kartını (ileride poker'de rakibin kartlarını) meraklı biri okuyabilirdi.

Bu yüzden kartları sunucu dağıtıyor ve her istemciye yalnızca görmeye hakkı olduğu bilgiyi gönderiyor. Kapalı kart istemciye null olarak gidiyor; gerçek kart sunucunun belleğinden hiç çıkmıyor.

// sunucu: her oyuncuya kendi görüşünü üretir
view(forId) {
  const dealerCards = T.dealer.cards.map(
    (c, i) => (T.dealer.hole && i === 1 ? null : c)   // kapalı kart yollanmaz
  );
  return { t:'state', phase:T.phase, turnP:T.turnP, deadline:T.deadline,
           dealer:{ cards: dealerCards, hole: T.dealer.hole },
           players: T.players.map(p => ({ id:p.id, name:p.name, chips:p.chips,
                                          hands:p.hands, ... })) };
}

Oda = Durable Object

Cloudflare'de "Durable Object", adı olan ve kendi belleğini koruyan küçük bir program. Oda kodu doğrudan bu nesnenin adı oluyor: KN439 yazan iki kişi aynı nesneye bağlanıyor, o nesnenin içindeki deste ve eller ikisi için de aynı. Odalar birbirinden tamamen bağımsız.

Tek çizim kodu. Sunucunun gönderdiği durum, tarayıcıdaki yerel oyun durumuyla aynı şekle sahip. Bu yüzden masayı çizen kod tek: çevrimiçi mod için ayrı bir arayüz yazılmadı, gelen durum aynı render()'a veriliyor. Koltuklar bakan oyuncuya göre döndürülüyor, herkes kendini saat 6'da görüyor.

Masa kilitlenmesin diye

Sırası gelen 30 saniye içinde oynamazsa sunucu onun yerine temel strateji oynuyor ve oyuncuyu afk işaretliyor — sonraki kararları beklemeden veriliyor, tek bir kişi telefonu bırakınca masa donmuyor. Bağlantı koparsa aynı kimlikle dönüldüğünde koltuk ve jetonlar korunuyor. Oda tamamen boşalınca masa sıfırlanıyor.

6. Yayına alma

Ana ekrana kurulabilir olması (PWA)

Üç parça yetiyor: manifest.webmanifest (ad, ikon, tam ekran), sw.js (dosyaları önbelleğe alan servis çalışanı) ve iOS meta etiketleri. Safari'de Paylaş → Ana Ekrana Ekle deyince uygulama gibi açılıyor, adres çubuğu yok, internetsiz de çalışıyor. Apple geliştirici hesabı gerekmiyor.

Buradaki en sinsi hata. Servis çalışanı index.html'i sürüm etiketi olmadan önbelleğe alıp "önce önbellek" stratejisiyle sunuyordu. Bir kez kurulduktan sonra sayfa hiçbir zaman ağdan tazelenmiyordu — telefonda ilk kurulan sürüm sonsuza dek kilitli kalıyordu. Ben düzeltmeler yayınlarken telefonda eski kod çalışıyordu. Çözüm: sayfanın kendisi önce ağdan, sürümlü dosyalar (?v=36) önbellekten. Ayrıca ekranda sürüm damgası: "bu eski sürüm mü?" sorusu bir daha tahmin olmasın diye.

7. İki ilginç algoritma

Saat düzeni yerleşimi

Koltuklar masanın etrafında sabit saat konumlarında. Konumlar yüzdeyle değil, masa ölçülüp pikselle veriliyor:

a  = (saat/12)·2π − π/2
x  = w/2 + rx·cos(a)·w
y  = h/2 + ry·sin(a)·h

Neden piksel? WebKit, yüksekliği belirsiz bir kapsayıcıda yüzdeli top değerlerini sıfır sayıyor. Yüzde kullanılınca iPhone'da bütün koltuklar üst üste biniyordu — masaüstünde hiç görünmeyen bir hata.

"feeling lucky" hilesi

İlk sürümde kartlar dağıtıldıktan sonra değiştiriliyordu — masadaki kart bir anda başkasına dönüşüyordu, gözle görülüyordu. Doğrusu: dağıtım başlamadan desteyi düzenlemek. draw() desteyi sondan çektiği için k'ıncı çekilen kartın destedeki yeri shoe[len − k]. Oyuncu sırası biliniyorsa, senin iki kartının denk geldiği yerlere bir As ve bir onluk takas ediliyor:

// n oyuncu, mi = benim sıram → dağıtım: p0..pn, krupiye, p0..pn, krupiye
const pAs = len − (mi + 1);          // 1. kartım
const pOn = len − (n + mi + 2);      // 2. kartım (krupiyeden sonra)
koy(pAs, c => c.v === 14);         // oraya bir As takas et
koy(pOn, c => bjValue(c) === 10);  // oraya bir onluk takas et

Kart eklenip çıkarılmıyor, yalnızca yer değişiyor — deste tutarlı kalıyor. Krupiye de blackjack yaparsa el berabere biteceği için onun kapalı kartı da değiştiriliyor. 25 el üst üste test edildi: 25'i de doğal blackjack. Çevrimiçi masada bilerek çalışmıyor — orada kartları sunucu dağıtıyor ve karşındaki insana karşı hile olurdu.
